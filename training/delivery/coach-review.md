## Review against evidence

Use **demonstrated**, **partial**, **not demonstrated** or **not observed** for each applicable criterion. “Not demonstrated” requires an observed attempt that did not meet the criterion. “Not observed” covers missing evidence or unattempted scope; it is not a low score. Record nonapplicability and its reason explicitly when the selected card does not test a criterion.

| Criterion | Evidence needed for “demonstrated” in the default routing task | Result | Evidence and assistance | Next practice |
|---|---|---|---|---|
| Explain the distinction | Separates administration access from business approval and can explain why | | | |
| Use scope and evidence | Routes each ticket, preserves its missing facts and identifies a bounded next check using the card's answer guidance | | | |
| Handle a changed condition | Identifies how the changed fact affects the decision without inventing authority or a completed action | | | |
| Explain limits and handoff | States the next owner, unresolved information and verification needed before claiming an outcome | | | |

For another card, replace the evidence column before delivery using that card's existing requirements. Keep the dated version. Do not silently switch criteria after seeing the learner's answer or turn a four-row discussion into a pass percentage. If a peer performs a later handoff exercise, record what the peer actually understood or did; an attractive handoff document alone does not establish usable transfer.

A correct assisted artifact may coexist with partial understanding or unobserved transfer. Mark the actual assistance even when the result is correct. If an unsafe inference appears, record it and return to practice; a strong answer elsewhere does not erase it. Do not let an AI-generated score substitute for the reviewer and evidence.
