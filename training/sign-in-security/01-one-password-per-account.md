# 1. One password per account

Reuse, not weakness, is the usual problem. One generated password per account, longest reach first.

Suggested time: 15–20 minutes. Work on paper or in a document.

**Outcome:** A personal plan for moving three accounts to unique, managed passwords, in order of risk.

Read the [shared fictional packet](source-packet.md). Keep it available throughout the lesson.

The password that hurts you is usually not the weak one. It is the good one you used twice. When a personal service is breached, the leaked email and password pairs are tried against work sign-in pages within days.

Guidance has moved on from symbols and forced changes. NIST says verifiers should not require periodic password changes, should check new passwords against lists of known compromised ones, and should force a change on evidence of compromise. [S1](sources.md#s1) A breach notice for a reused password is that evidence.

A password manager makes this realiztic. It generates, stores, and fills a long random password, so you never type or remember it. You memorise one long passphrase for the manager and protect it with your strongest second factor. D3 3.1 makes the firm's manager mandatory.

Hashed passwords can be cracked, and the notice date is not the breach date. Order your moves by reach: work email first, because it resets everything else, then money or client files, then the breached service. The FBI gives the same advice: unique passwords. [S5](sources.md#s5)

## Worked example: From stronger to separate

**Before**

Priya's first thought: "I will make the Pantry Box password longer with more symbols. My work password is already long, so it is fine."

**After**

Priya's revised plan: "Work email first, generated by the manager. Then file sharing, same way. Then Pantry Box. I tell Lena before I start so she can watch the sign-in report."

**Why:** Reuse is the fault, not strength. The mailbox can reset everything else, so it moves first. Telling Lena first separates deciding from doing.

## Check one decision

Priya's Pantry Box password is also her work email password. Which first step fits D1 and D3?

- **A.** Change the Pantry Box password first, since that is where the breach was.
- **B.** Change the work email password to a manager-generated one, then the others, and tell the technology team.
- **C.** Wait for Pantry Box to confirm the hashed passwords were cracked.

<details>
<summary>Answer and feedback</summary>

The supported choice is **B**.

**A:** The leaked password already opens Priya's work mailbox, and D3 3.2 treats a breach notice for a reused password as evidence to change it. Pantry Box has the least reach, so it moves last.

**B:** This fits D1 and D3: the mailbox has the longest reach, the manager makes the password unique, and Lena can watch for activity while Priya works.

**C:** D1 gives no timeline, and D3 3.2 needs only evidence the password may be known, not proof of cracking. Waiting leaves the mailbox open; D2 shows attempts on Priya's work account by the 18th.
