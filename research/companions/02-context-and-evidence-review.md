## Compare three arrangements

| Condition | Record | Check |
| --- | --- | --- |
| Curated packet | Selection rule, included and omitted sources, preparation time. | Did curation remove an important exception? |
| Full authorized set | Included sources, order, size, truncation, and preparation time. | Did the model resolve dates and contradictions rather than merely receive them? |
| Retrieval | Index/version, retrieval rule, returned source IDs, failures, and setup effort. | Was necessary evidence retrieved, and were unsupported claims left unresolved? |

Each condition must have access to the facts required to answer correctly. Separately record what the invocation actually saw. A comparison that withholds decisive evidence from one condition tests more than context strategy.

## Source register

In `evidence-register.csv`, give each source/version a stable ID. Record origin, document date, retrieval time, owner, permitted use, authoritative status, conflicts, supersession, and derived summaries. A source can be current but irrelevant; an older document can remain authoritative for a historical question. State the scope of authority.

Use status values such as current, superseded, missing, inaccessible, conflicting, and unverified. Do not turn an inaccessible source into a claim that it contains no relevant information.

## Memory correction test

Record the saved fact, its source/date/scope, the storage location, and who may amend it. Introduce a fictional source revision. Test whether the old fact is retired or marked disputed, retrieval returns the applicable version, and linked summaries are rechecked. Verify both the source record and a fresh answer; a successful edit notification alone is insufficient.
